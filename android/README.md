# SaintsRM Android smoke test

This is milestone 0 for the SaintsRM native Android port.

It deliberately does **not** contain Saints Row game code or game data. The purpose is to establish a reliable Android/ARM64 platform boundary before porting the Saints Reborn game layer.

## What it tests

- arm64-v8a native build;
- Android Vulkan instance and physical-device discovery;
- Android `ANativeWindow` → Vulkan surface creation and recreation;
- runtime page-size detection;
- 16 KiB-compatible native linker flags;
- `SIGSEGV` interception with `SA_SIGINFO` and `SA_ONSTACK`;
- current-thread alternate signal stack;
- protected-page `mprotect(PROT_NONE)` fault and controlled AArch64 continuation;
- signal chaining to the previous/default SIGSEGV disposition for unrelated faults;
- basic dynamic-loader operation;
- Activity/surface destruction, recreation, pause/resume and `onTrimMemory` handling.

## Important limitation

The smoke test installs an alternate signal stack for the current native thread only. The final runtime must install an alternate stack for every native guest/runtime thread before enabling guest fault recovery.

The protected-page handler intentionally recognizes only the exact instruction generated by this test. It is **not** the Saints Row fault handler and is not a general AArch64 instruction decoder.

## Device requirement

The first validation target is a real ARM64 Android device. An emulator build is useful for CI compilation but is not considered proof of correct Vulkan, signal, memory-protection, or thermal behavior on mobile SoCs.

## Logs

Use:

```text
adb logcat -s SaintsRM-Smoke
```

For crashes, also collect the Android tombstone from the device. The smoke test records the last intercepted fault address, PC and instruction in the test result and logcat.

## Next milestone

After this smoke test is validated on a real device, integrate the Android platform layer with ReXGlue, then port Saints Reborn's game-specific fault semantics. The Windows VEH and x86-64 decoder must remain intact for the Windows target until the ARM64 differential tests prove that the corresponding responsibilities are covered.
